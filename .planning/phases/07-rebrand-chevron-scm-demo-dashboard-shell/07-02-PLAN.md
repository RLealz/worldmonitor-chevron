# Plan 02 - Rebrand Metadata Settings Loading And Demo Docs

## Goal

Make browser-visible branding, loading states, settings shell copy, and SCM demo docs align with the standalone Chevron SCM demo product while preserving public-data-only safety language.

## Must Haves

- SCM page title, application metadata, and visible loading/skeleton labels use Chevron SCM demo framing.
- SCM settings shell does not surface WorldMonitor product promotion, author attribution, GitHub stars, login/signup, Pro, subscription, pricing, or API-key upsell language.
- SCM demo docs use Chevron SCM demo framing where they are demo-facing.
- Technical docs and implementation identifiers are not blindly renamed when WorldMonitor is the actual API/header/proto name.
- Public/open-source-data-only disclaimers and no-private-Chevron-data language remain visible.

## Risks

- `index.html` is shared across variants. Avoid a static rewrite that damages non-SCM SEO or product metadata.
- A broad docs rewrite could rename technical API identifiers incorrectly. Limit docs edits to SCM demo-facing docs and labels.
- Removing metadata authorship for SCM should not remove required license, repository, or technical provenance from non-demo contexts.
