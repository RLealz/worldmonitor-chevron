# Plan 01 - Add Variant-Scoped Chevron SCM Brand System

## Goal

Create a single SCM-aware branding source and use it to rebrand the visible dashboard shell without changing non-SCM product variants.

## Must Haves

- SCM shell uses `Chevron SCM Demo Dashboard` or the approved equivalent from the branding helper.
- SCM header renders both the approved demo logo and Chevron logo with stable dimensions and accessible image text.
- SCM header, mobile menu, and footer do not display WorldMonitor logo text, author credit, GitHub star count, or GitHub product-promo link.
- Non-SCM variants keep their existing header/footer brand behavior.
- Branding decisions are centralized in a variant-scoped helper/config, not scattered across layout code.

## Risks

- Header layout can become crowded if two logos and the variant switcher compete for space. Use stable dimensions and responsive hiding/stacking rules.
- Logo assets must be the approved demo/Chevron assets. If assets are unavailable, stop and document the blocker rather than inventing an unofficial logo.
- Do not remove GitHub/author surfaces globally unless non-SCM tests confirm intended behavior.
