# Plan 01 - Build Supplier Risk Signals Model

## Goal

Create a deterministic, public-data-only supplier-risk model and demo archetype fixtures that can power SCM supplier cards without implying customer-private supplier knowledge.

## Must Haves

- Supplier records are explicitly synthetic archetypes or public-signal summaries.
- Risk output combines country/product, route/chokepoint, sanctions/trade, materials relevance, and data freshness inputs.
- Every risk claim/evidence item carries source, timestamp, confidence, and reason.
- The model reuses `computeSupplierRouteRisk()` for route/chokepoint exposure.
- Tests cover stable, sanctions-hit, route-disrupted, stale-data, and low-confidence scenarios.

## Risks

- Scoring weights can imply more precision than the public data supports. Keep weights simple, documented in code names, and exposed through reasons/confidence.
- Importing config from utilities can break dependency direction. Keep the pure scoring function in `src/utils/` and place fixtures in `src/config/`.
- Phase 3 will deepen compliance; this plan should only consume bounded sanctions/trade signal inputs with provenance.
