# Plan 03 - Guardrails and Verification

## Goal

Lock supplier-risk behavior and demo-safety posture with focused automated tests, static guardrails, and verification evidence.

## Must Haves

- Tests cover stable, sanctions-hit, route-disrupted, stale-data, and low-confidence scenarios.
- Tests prove evidence fields include source, timestamp, confidence, and reason.
- Tests prove supplier records are synthetic/public-signal summaries, not private supplier data.
- SCM variant tests prove the supplier-risk panel is registered by default.
- Typecheck and boundary lint pass or documented unrelated blockers are captured with evidence.

## Risks

- Existing Windows script issues may block `npm run build` or Playwright. Use the documented direct SCM build path and record blockers.
- Guardrails may need updates after Plan 02 introduces new file names. Keep tests broad enough to cover the new supplier-risk source set without overfitting exact markup.
- Boundary lint may catch accidental layer inversions if the model imports fixtures from utilities. Fix by moving shared types to `src/types/` and demo records to `src/config/`.
