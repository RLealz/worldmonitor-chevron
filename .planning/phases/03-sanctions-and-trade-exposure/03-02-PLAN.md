# Plan 02 - Add SCM Sanctions and Trade Context

## Goal

Make existing sanctions and trade-policy panels show SCM-specific public screening context, provenance, and supplier/country/material links while preserving existing behavior for non-SCM variants.

## Must Haves

- SCM users can view sanctions pressure and trade-control signals from public sources.
- Panel copy frames outputs as public screening/exposure signals, not final legal determinations.
- Provenance is visible: source/list/date/version where available, with clear fallback when public sources omit it.
- Sanctions/trade exposure relates to supplier archetype, country, route, and material context.
- Existing non-SCM variants keep current defaults and panel behavior except for shared-safe provenance improvements.

## Risks

- Enhancing large existing panels can create noisy diffs. Keep SCM context in small helper render methods and optional setter methods.
- Trade Policy has runtime feature gating. Do not bypass gating; show SCM context only around public data that is actually available.
- If panel CSS grows too much inside `base-layer.css`, move styles into a dedicated imported CSS file following the supplier-risk panel pattern.
