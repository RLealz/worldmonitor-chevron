# Plan 01 - Add Public Artifact Safety Guardrails

## Goal

Create deterministic static guardrails that scan SCM source, docs, public artifacts, generated OpenAPI, bootstrap/cache surfaces, and planning docs for proprietary-looking Chevron SCM data.

## Must Haves

- Guardrail distinguishes forbidden positive claims from legitimate out-of-scope language.
- Scan covers public docs, `public/`, generated/public OpenAPI, SCM source/config/tests, bootstrap keys, analytics/event labels where practical, and planning docs.
- Guardrail blocks private-data-shaped fields and claims: supplier rosters, internal routes, shipments, vessel nominations, inventory, contract pricing, facility-sensitive details, legal compliance finality, and production restricted-party case records.
- Guardrail allows explicit demo limitations that say these data types are not included.

## Risks

- Over-broad patterns can block legitimate limitation docs. Keep allowlists narrow and require explicit negative wording.
- Generated artifacts may not exist until build steps run. Generate `public/openapi.yaml` before final artifact scanning.
- Static scanning is not a full data-governance program; it is a demo safety net.
