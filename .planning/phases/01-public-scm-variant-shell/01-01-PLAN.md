# Plan 01 — Register the SCM Variant

## Goal

Make `scm` a first-class supported variant with public-data-safe metadata and navigation, without changing runtime data contracts.

## Must Haves

- `VITE_VARIANT=scm` resolves as `scm` rather than falling back to `full`.
- Localhost and Tauri stored variant validation accept `scm`.
- Hostname detection supports `scm.` if consistent with existing variant host patterns.
- `VARIANT_META.scm` exists with generic energy SCM wording.
- Navigation exposes the SCM variant without implying proprietary Chevron access.
- Copy says public/open-source-data demo or equivalent safe framing.

## Risks

- `scm` may require favicon assets if the Vite plugin rewrites favicons for every non-full variant. If assets are missing, either reuse existing full/energy assets for SCM or adjust the rewrite so SCM does not point at missing files.
- Navigation may use translations rather than literal labels. Follow existing patterns and keep copy minimal.
