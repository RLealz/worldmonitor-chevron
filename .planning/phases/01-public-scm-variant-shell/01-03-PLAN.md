# Plan 03 — Guardrails and Smoke Verification

## Goal

Lock the SCM shell with focused tests and document the verification path.

## Must Haves

- A focused static test proves SCM variant registration, metadata, panel defaults, map layer defaults, and safe framing.
- A focused static test proves SCM empty/degraded-state copy distinguishes public-data absence and demo assumptions from proprietary-data absence.
- Typecheck passes.
- Boundary lint passes.
- A browser/E2E smoke path is run, or a clear blocker is recorded with evidence.
- No production/private data assumptions are introduced by tests or fixtures.


## Risks

- Playwright may be too slow or unavailable locally. If so, keep the static guardrail test and typecheck/lint as the required automated proof, then record the smoke blocker.
- Static tests can overfit exact source text. Keep assertions focused on behavior-critical identifiers and safety strings.
