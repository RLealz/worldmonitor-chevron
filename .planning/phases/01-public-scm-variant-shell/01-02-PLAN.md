# Plan 02 — Curate Panels, Layers, and Demo Framing

## Goal

Define the SCM variant's default dashboard shape from existing public-data panels and map layers.

## Must Haves

- `VARIANT_DEFAULTS.scm` exists and includes SCM-relevant existing panels.
- SCM panel labels are generic/public-data-safe.
- SCM default map layers emphasize supply-chain, energy, sanctions, route, and materials context.
- SCM mobile map layers are performance-aware and not overly dense.
- Data loader conditions include `scm` wherever existing public supply-chain/trade/energy loading is variant-gated.
- SCM-facing empty and degraded states distinguish missing public data, stale data, unavailable upstreams, and demo-only assumptions.
- No new proprietary-looking data or private Chevron assumptions are introduced.

## Risks

- Some candidate panels may be premium-gated or not instantiated in the current layout. If a panel id is not registered, omit it rather than creating new behavior in Phase 1.
- Too many map layers can make the shell noisy. Favor operational SCM relevance over breadth.
- Existing panel response shapes may not expose every freshness distinction. Do not fabricate precision; use clear fallback copy and defer richer state modeling if needed.
