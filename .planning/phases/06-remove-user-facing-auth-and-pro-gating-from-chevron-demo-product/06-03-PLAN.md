# Plan 03 - Add SCM No-Gating Guardrails And Browser Smoke

## Goal

Lock Phase 6 behavior with automated tests and final verification proving the SCM demo shows no user-facing auth/Pro gating while preserving public-data safety language and backend protections.

## Must Haves

- Static tests fail if SCM-facing source reintroduces login, signup, account, profile, Pro, pricing, subscription, upgrade, locked-feature, or unlock copy.
- Tests explicitly allow backend-only auth/security/protection language in `api/`, `server/`, and operational docs.
- Browser smoke proves the SCM variant loads without visible auth/Pro gating and with core SCM panels still usable.
- Final verification records what was run, what passed, and any residual manual review gaps.

## Risks

- Browser smoke may need resilient selectors because the dashboard has async data loading and optional upstream data.
- Pro-site bundles under `public/pro/` may still exist for non-SCM product routes. Guardrails should focus on the SCM demo experience unless deployment routing serves those assets.
- Backend-only auth/protection terms must remain allowed in server and API code.
