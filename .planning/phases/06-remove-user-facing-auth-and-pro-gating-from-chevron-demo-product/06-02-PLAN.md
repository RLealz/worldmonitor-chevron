# Plan 02 - Ungate SCM Panels, Layers, And Settings UX

## Goal

Ensure the SCM demo remains usable without a user account by removing visible locked-feature states, Pro badges, upgrade CTAs, free-tier limits, and account-gated settings from SCM-reachable dashboard surfaces.

## Must Haves

- SCM panel content is either visible, omitted from the variant, or shown as public-data unavailable/degraded. It is never blocked behind sign-in or Pro copy.
- SCM map layer toggles do not show lock glyphs, disabled Pro-only toggles, or `PRO` badges.
- SCM settings do not show account-gated API key management, billing, subscription, upgrade, or Sign In CTAs.
- Server-side premium and entitlement checks remain intact for routes that still require them.

## Risks

- Some panels call server routes that are still account- or entitlement-gated. The SCM UI should omit or degrade those sections rather than weakening server checks.
- Saved layout state can re-enable non-default panels. Tests should cover persisted panels where practical.
- "Tier" can also mean source credibility or risk tier. Guardrails must target pricing/access-tier copy, not analytical source-tier labels.
