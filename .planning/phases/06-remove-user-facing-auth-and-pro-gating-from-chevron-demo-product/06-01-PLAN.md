# Plan 01 - Suppress Account And Commerce UX In The SCM Shell

## Goal

Make the SCM variant load as a standalone demo shell with no visible login, signup, account menu, user profile, Pro, subscription, pricing, checkout, or billing-entry UX.

## Must Haves

- SCM users see dashboard controls, settings, public-data framing, and SCM panels without being asked to sign in.
- Header, mobile menu, footer, and settings entry points do not display account, Pro, pricing, subscription, upgrade, checkout, or billing copy in SCM.
- Main WorldMonitor variants keep their existing auth and Pro behavior.
- Backend-only auth, API-key, Redis, CORS, and operational protection remain untouched.

## Risks

- Removing the auth widget must not remove settings access; settings already has separate header and mobile mounts.
- Checkout/entitlement services may have side effects used by non-SCM variants. Gate by SCM policy only.
- Static tests should allow backend-only auth terms, otherwise they will block required server protections.
